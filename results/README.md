# Results / Resultados

---

## English

### Contents

This folder contains the comparative evaluation results of the three experimental configurations described in the paper:

| File | Configuration |
|---|---|
| [`comparison_7B.json`](comparison_7B.json) | (A) Qwen2.5-7B-Instruct, with packing |
| [`comparison_1_5B.json`](comparison_1_5B.json) | (B) Qwen2.5-1.5B-Instruct, with packing |
| [`comparison_7B_no_pack.json`](comparison_7B_no_pack.json) | (C) Qwen2.5-7B-Instruct, without packing |

Each JSON file contains:

- `qwen_base` — responses of the base model
- `sl_cai` — responses of the model after supervised fine-tuning (SFT)
- `rl_cai` — responses of the model after direct preference optimization (DPO)
- `scores` — evaluation scores assigned by the judge model (SmolLM2-1.7B-Instruct)

### Naming convention

Packing is the default state of the training pipeline. It is only indicated explicitly in the filename when it is disabled (suffix `_no_pack`).

### Structure of the scores

Each score entry contains:

- `prompt` — truncated prompt (60 characters)
- `rl_vs_base` — probability that the RL-CAI response is preferred over the base response
- `rl_vs_sl` — probability that the RL-CAI response is preferred over the SL-CAI response
- `sl_vs_base` — probability that the SL-CAI response is preferred over the base response

Values range from 0 to 1. A value above 0.6 indicates a clear preference; below 0.5 indicates no substantial improvement.

### How the averages are calculated

The RL>SL average reported in the paper for each configuration is calculated as the **average of the 24 individual prompts** (2 prompts per each of the 12 principle categories). This method reproduces the values reported in the paper:

| Configuration | RL>SL average |
|---|---|
| (A) 7B, with packing | 0.324 |
| (B) 1.5B, with packing | 0.523 |
| (C) 7B, without packing | 0.474 |

### Note on non-determinism

The evaluation pipeline has inherent non-determinism:

- Model generation uses sampling with temperature (0.7).
- The judge model (SmolLM2-1.7B-Instruct) selects the evaluation principle randomly for each comparison.
- The preference dataset is small (24 pairs).

As a result, repeated executions of the same experiment may produce different averages. The results reported here correspond to a single run per configuration.

### How the results were generated

The three JSON files were generated by executing the evaluation notebook on Google Colab with a Tesla T4 GPU, using:

- The trained LoRA adapters (`modelo_lora.zip` for SFT, `rl_cai_lora.zip` for DPO)
- The Cultural Constitution (`codigo_moral_v2.1.json`)
- The Qwen2.5-Instruct models (7B and 1.5B)
- The feedback model `HuggingFaceTB/SmolLM2-1.7B-Instruct`

The training and evaluation notebooks are in [`../training/`](../training/).

## Español

### Contenido

Esta carpeta contiene los resultados de evaluación comparativa de las tres configuraciones experimentales descritas en el artículo:

| Archivo | Configuración |
|---|---|
| [`comparison_7B.json`](comparison_7B.json) | (A) Qwen2.5-7B-Instruct, con packing |
| [`comparison_1_5B.json`](comparison_1_5B.json) | (B) Qwen2.5-1.5B-Instruct, con packing |
| [`comparison_7B_no_pack.json`](comparison_7B_no_pack.json) | (C) Qwen2.5-7B-Instruct, sin packing |

Cada archivo JSON contiene:

- `qwen_base` — respuestas del modelo base
- `sl_cai` — respuestas del modelo tras el ajuste supervisado (SFT)
- `rl_cai` — respuestas del modelo tras la optimización directa de preferencias (DPO)
- `scores` — puntuaciones asignadas por el modelo juez (SmolLM2-1.7B-Instruct)

### Convención de nombres

El packing es el estado por defecto del pipeline de entrenamiento. Solo se indica explícitamente en el nombre del archivo cuando se desactiva (sufijo `_no_pack`).

### Estructura de los scores

Cada entrada de score contiene:

- `prompt` — prompt truncado (60 caracteres)
- `rl_vs_base` — probabilidad de que la respuesta RL-CAI sea preferida sobre la del modelo base
- `rl_vs_sl` — probabilidad de que la respuesta RL-CAI sea preferida sobre la del SL-CAI
- `sl_vs_base` — probabilidad de que la respuesta SL-CAI sea preferida sobre la del modelo base

Los valores van de 0 a 1. Un valor superior a 0.6 indica una preferencia clara; por debajo de 0.5 indica que no hubo mejora sustancial.

### Cómo se calculan los promedios

El promedio RL>SL reportado en el artículo para cada configuración se calcula como el **promedio de los 24 prompts individuales** (2 prompts por cada una de las 12 categorías de principios). Este método reproduce los valores reportados en el artículo:

| Configuración | Promedio RL>SL |
|---|---|
| (A) 7B, con packing | 0.324 |
| (B) 1.5B, con packing | 0.523 |
| (C) 7B, sin packing | 0.474 |

### Nota sobre el no-determinismo

El pipeline de evaluación tiene no-determinismo inherente:

- La generación de los modelos usa sampling con temperatura (0.7).
- El modelo juez (SmolLM2-1.7B-Instruct) selecciona el principio de evaluación de forma aleatoria para cada comparación.
- El dataset de preferencias es reducido (24 pares).

Como resultado, ejecuciones repetidas del mismo experimento pueden producir promedios distintos. Los resultados aquí reportados corresponden a una única ejecución por configuración.

### Cómo se generaron los resultados

Los tres archivos JSON se generaron ejecutando el notebook de evaluación en Google Colab con una GPU Tesla T4, usando:

- Los adapters LoRA entrenados (`modelo_lora.zip` para SFT, `rl_cai_lora.zip` para DPO)
- La Constitución Cultural (`codigo_moral_v2.1.json`)
- Los modelos Qwen2.5-Instruct (7B y 1.5B)
- El modelo de retroalimentación `HuggingFaceTB/SmolLM2-1.7B-Instruct`

Los notebooks de entrenamiento y evaluación están en [`../training/`](../training/).
